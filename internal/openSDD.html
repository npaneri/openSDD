🚀 Quick Start — Three Steps

No need to copy sdd/ into your repo. The methodology lives in the OpenSDD ecosystem.

  1. Download CLI from GitHub and run via `npx opensdd`
  2. Choose your path:
    • Kit (recommended): opensdd kit install node-express — generates complete SpecSet with Express + Zod + vitest pre-configured
    • CLI: opensdd kickoff — 3 questions, auto-detects framework; generates SpecSet
    • Skill-aware assistant: "Follow OpenSDD kickoff for my API" — assistant reads methodology
  3. Continue the cycle: 
    # View roadmap status
opensdd status

# Start next phase
opensdd phase 1

# List available kits
opensdd kit list

📖 CLI Reference

opensdd --help — Document all subcommands
opensdd kickoff — Phase-0: 3 questions, auto-detects framework, generates idea.md + skeleton
opensdd phase — Generate Phase N skeleton (1-5), update roadmap status
opensdd status — View roadmap status table
opensdd kit install — Install pre-built kit (node-express, python-fastapi, go-fiber)
opensdd kit list — List available kits

🛠️ Troubleshooting

"sdd/" folder in repo: Remove it; use opensdd kickoff instead. The methodology is accessed via the npm package/CLI, not by copying folders.

Phase not generating: Check your ideas.md has sufficient info. Run opensdd kickoff -f ideas.md to re-trigger with new input.

Tech stack pre-fill wrong: Re-run opensdd kickoff -f ideas.md with corrected ideas file, or edit tech-stack.md directly (safe; low breakage risk).

SpecSets not tracked in git: Add specs/ to your repo's .gitignore. OpenSDD-generated SpecSets are specification artifacts, not source code.
